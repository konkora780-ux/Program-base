# Iリーグ デジタルプログラム（最小版）

有料購入者だけが閲覧コードで見られる、Iリーグの公式プログラムWebアプリです。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 閲覧アプリ（購入者が見る画面。スマホ表示＋A4印刷） |
| `admin.html` | 管理画面（年度・Excel取り込み・写真・日程・閲覧コード） |
| `config.js` | Supabase の接続先（URL と anon key）を書くファイル |
| `supabase/schema.sql` | データベースの設計図。Supabase で1回実行する |
| `template/Iリーグ_掲載情報ひな型.xlsx` | 各チームに配るExcel |
| `template/Iリーグ_日程ひな型.xlsx` | 管理者が日程をまとめて入れるExcel |
| `demo-data.js` | 見本表示用の架空データ（`index.html?demo=1` のときだけ使う） |
| `lib/` | 部品（Supabase接続用・Excel読み取り用）。インターネット上の配布元に頼らないよう同梱 |

## 見本で動きを確認する

`index.html?demo=1` を開き、コード `DEMO-DEMO-DEMO` を入れると架空データで全画面を確認できます。
（GitHub Pages に置いた後なら `https://＜公開先＞/index.html?demo=1`）

## 本番のセットアップ手順

1. **Supabase のプロジェクトを作る**（協会名義のアカウント推奨）。リージョンは Tokyo を選ぶ。
2. 左メニュー **SQL Editor** を開き、`supabase/schema.sql` の中身を全部貼り付けて **Run**。
3. **Authentication → Sign In / Providers** で「Allow new users to sign up（新規登録を許可）」を **オフ** にする。
   （管理者以外がアカウントを作れないようにするため。作られても管理者表に入っていなければ何もできませんが、二重の鍵です）
4. **Authentication → Users → Add user** で管理者を作る。Email address は「ログインID@ileague.example」（例：`ileague@ileague.example`）、Auto confirm user にチェック。
   管理画面のログインでは「@」より前（例：`ileague`）だけ入力すればよい。
5. SQL Editor で次を実行し、その人を管理者にする（メールアドレスは置き換え）：
   ```sql
   insert into public.admins(user_id, note)
   select id, '管理者' from auth.users where email = 'ileague@ileague.example';
   ```
6. **Project Settings → API** の「Project URL」と「anon public key」を `config.js` に貼る。
   ※ `service_role` key（秘密の鍵）は絶対に貼らないでください。
7. GitHub にリポジトリを作り、このフォルダの中身を入れて **GitHub Pages** を有効にする。
8. `admin.html` を開いてログイン → 「年度・挨拶」で年度を作る → Excel取り込み → 写真 → 日程 → コード発行。

## しくみ（安全のための工夫）

- **データはHTMLに入っていません。** 閲覧者が呼べるのは「コードを渡すと中身を返す関数」だけで、表を直接読むことはできません（RLS＋権限の取り消しで二重に禁止）。
- **コードはデータベースに復元できない形（ハッシュ）でだけ保存**します。万一データベースの中身が漏れても、コードそのものは分かりません。そのため、コード本体は発行直後の画面とCSVでしか見られません。
- **掲載不同意（Excelで「×」）の選手は、購入者向けの画面・印刷に一切出ません。** 運営用にデータは保存し、管理者ログイン中の管理画面「チーム・写真 → 名簿」でだけ確認できます。購入者向けの関数が同意済みの選手だけを返すので、画面の作りに関係なく×の選手のデータは購入者の端末に届きません。
- **写真は「写真を掲載」にチェックしたチームだけ**表示されます。写真もコード照合を通った人にだけ渡します。
- 印刷すると、全ページに **購入番号（コードそのものではない番号）** の透かしと「無断複製・配布禁止」が入ります。印刷物から購入者を特定でき、印刷物を見てもコードは分かりません。
- 検索エンジンに載らない設定（noindex）にしています。

## リーグ（ディビジョン）

- 年度を作ると、既定のリーグ（DIVISION Ⅰ／Ⅱ／Ⅲ／Ⅳ北／Ⅳ南／Ⅳサテライト）が自動で入ります。管理画面「年度・挨拶」で追加・名前変更・並べ替え・削除ができます。
- どのリーグのページに載るかは **選手ごとの所属リーグだけ** で決まります（学校の「主な所属リーグ」はありません）。Excel の選手名簿「所属リーグ」欄（リスト選択）か、管理画面の「名簿」で変更できます。
- **所属リーグが空欄の選手は「どのリーグにも所属しない」扱い**です。リーグのページには出ず、前半の学校のチーム紹介（全選手）にだけ載ります。
- **冊子の構成**：表紙 → あいさつ → 日程・対戦表 → 前半「チーム紹介」（全学校の写真・紹介文・ユニフォーム・監督コーチ・全選手）→ 後半 リーグごとの扉と、各校のページ（前半と同じ形で、選手だけそのリーグの登録選手）。アプリのチーム一覧も同じ順です。
- **デザイン**：案A「スタジアム・ナイト」（濃紺×黄緑、見出しは Zen角ゴシック、数字は Oswald）。文字の形は Google Fonts から読み込みます。
- **1つの学校が複数リーグにチームを持てます。** 学校は1つのExcelにまとめ、選手ごとの所属リーグで「学校×リーグ」のチームページに分かれます（例：架空A高校のⅠ部ページとⅣサテライトページ）。アプリのチーム一覧と冊子は、リーグの並び順 → 学校の並び順で並びます。今はチーム写真・紹介文・ユニフォーム・スタッフを学校で共通にしています。
- Excel のリストは各ファイルの「リーグ一覧」シートが元です。リーグ名を変えたら、配布前にこのシートも同じ名前に直してください（取り込み時、名前が一覧にないとエラーで知らせます）。

## 仮で決めた点（あとで変更できます）

| 項目 | 仮の決め方 | 理由 |
|---|---|---|
| 掲載同意の入力 | Excelの「掲載不同意」欄にリストから「×」を選ぶ。空欄＝同意済みとして掲載 | こんちゃんの指定（2026-11-08） |
| ×の選手 | 運営用には保存・管理画面で閲覧可。購入者の画面・印刷には背番号も含め一切出さない | こんちゃんの指定（2026-11-08） |
| チーム写真 | 登録すれば掲載（×の選手が写っていても掲載してよい）。管理画面の「写真を掲載」のチェックを外すと非表示 | こんちゃんの指定（2026-11-08） |
| コードの有効期間 | 年度ごと（初期値 4/1〜翌3/31） | 年度単位の販売のため |
| コードの形 | 12文字（例：K7QM-2XPA-9RTD）。見間違えやすい 0/O/1/I は使わない | 推測されにくく、入力しやすい |
| 同時に使える台数 | 制限なし（利用回数と最終利用日時を記録） | 制限の仕組みは第2段階で検討 |
| ユニフォームの表記 | 現行冊子に合わせ「シャツ・ショーツ・ストッキング」 | 冊子と同じ見た目にするため |
| 1チームの人数 | Excelひな型は200行 | 最大200人とのことのため |

## 確認が必要な点

1. 現行冊子にあって、まだ入れていない項目を入れるか：**エンブレム、チーム紹介文、引率責任者、主将、マネージャー**
2. 「空欄＝同意済み」なので、チームが×を付け忘れると同意のない選手が載ってしまう。ひな型の説明で注意喚起しているが、取り込み前にチームへ確認する運用が必要
7. ×の選手の情報も運営用に保存するため、管理者アカウントの管理（パスワード・人数を絞る）と、年度終了後の削除の決まりが必要
3. Supabase の無料プランは、一定期間使われないと一時停止する条件がある（最新の条件は Supabase の料金ページで要確認）
4. Excel読み取り部品（SheetJS）は npm 版 0.18.5 を同梱。これには「細工されたExcelを開くと問題が起きうる」既知の弱点があり、公式配布元の最新版（0.20.3 以降）への差し替えを推奨。各チームから届くファイルなので危険は低いが、本番前に差し替えたい
5. スクリーンショットや印刷物の再配布は技術では完全には防げない（透かしは抑止）。利用規約での禁止が必要
6. 協会としてのプライバシーポリシー（個人情報の扱いの説明文）の用意
